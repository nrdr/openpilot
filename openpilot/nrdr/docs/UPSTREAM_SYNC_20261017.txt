Model/runtime migration (explicitly approved)

The full generic ONNX/warp compiler, native and legacy model adapters, current
default CD210 model, precompiled Cinque Terre v2 Chestnut default, and paired
Chestnut telemetry are included. hardwared owns USB/power/link chestnutState;
modeld owns chestnutGpuState. No duplicate publisher owns the same service.
Existing hardware liveness/cache workers are preserved.

Firmware calibrations, measured SR/geometry, speed-dependent firmware delay
schedules, lane-change policy, and source timestamps remain NRDR-owned. Both
model runners stamp the same action horizon/frame identity before adjacent
modelV2/modelDataV2SP publications. This migration is NOT evidence that the
observed controlsd scheduling shortfall, early turn-in or PCM hesitation is fixed.

New compiler builds use temporary outputs, reload/check their ABI, then replace
the model and provenance stamp. A failed compile leaves the prior artifact
untouched; mismatched/interrupted artifact+stamp pairs fail admission. SCons
declares both outputs, so a missing stamp forces rebuilding. Both C3/C4 camera
warps are covered; compiler CPU affinity is inherited, not pinned to offline CPU7.
Chestnut warp link failure returns a build error rather than fake success.
Release gates check source/compiler hashes, QCOM backend, all shared-camera
warps, and exact model weights without executing pickle contents.
